# [#](#创建移动应用) 创建移动应用

创建移动应用账号前需先完成微信开放平台账号注册，详情查看下方指引。

## [#](#一、注册微信开放平台账号) 一、注册微信开放平台账号

微信开放平台网址为：<https://open.weixin.qq.com/>，更多详细的操作指引可查看[注册开放平台](https://developers.weixin.qq.com/doc/oplatform/Third-party_Platforms/2.0/operation/open/create)。

注意：

- 用于注册微信开放平台账号的邮箱必须是唯一的，即不能使用已经注册为小程序、公众号或者已绑定微信的邮箱账号，必须使用一个从来未注册过微信生态任何产品的邮箱。

![](https://testchu-7gy8occc8dcc14c3-1304825656.tcloudbaseapp.com/img%2Fmelody%2F202406101743693.png)

- 移动应用的主体需与多端应用绑定的「小程序」是同主体或者关联主体，而移动应用的主体则是继承的微信开放平台主体，因此在创建微信开放平台时请注意选择正确的主体信息，否则后面将无法正常进行绑定。

## [#](#三、创建移动应用账号) 三、创建移动应用账号

### [#](#_3-1-创建方式) 3.1 创建方式

开发者可通过「直接创建」或「复用多端应用快速创建」的方式创建移动应用，两者的区别为：

#### [#](#_3-1-1-直接创建) 3.1.1 直接创建

按照「微信第三方平台-移动应用」指引提供移动应用名称、英文名称（选填）、移动应用简介、英文简介（选填）、应用官网、移动应用图片、应用已上架信息、应用类目、APP 运行流程图以及开发信息等信息提交审核后创建移动应用。

#### [#](#_3-1-2-复用多端应用快速创建) 3.1.2 复用多端应用快速创建

通过该方式创建的移动应用账号的图标、名称、简介均来源于「该多端应用所绑定的小程序」，无需重复提供资质进行名称、图标等信息的审核。

此外，通过此方式创建移动应用时「应用官网」为非必填项，不填时则默认使用「该多端应用所绑定的小程序」作为线上官网内容进行审核，进一步降低开发者准备网站内容的门槛。

补充，此种方式有前置条件：

1. 小程序账号已经绑定多端应用。
2. 且绑定小程序账号的头像、昵称、简介是完善的；状态是正常的，以及是已发布上线的。
3. 并且，该小程序可以被任何人访问的，无需特定的 B 端账号才可访问。

因此，建议开发者选择「直接创建」的方式创建移动应用，下文也将对此种方式进行介绍。

### [#](#_3-2-「基本信息」填写) 3.2 「基本信息」填写

名称和简介需如实填写，且需要遵守[移动应用名称填写规范](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/operation)，否则会被驳回。

应用图标，除了有像素的要求之外也需要遵守[移动应用图标规范](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/operation)，否则会被驳回。

官网：官网内容需规范，包括应用提供的服务功能详情、用户协议、版权所有者、网站备案信息、联系方式等；且需要遵守[移动应用官网规范](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/operation)，否则会被驳回。

官网注意事项：

1. 所提供的官网不得是无法访问应用详细信息的登录界面，如网站需登录后才可访问，建议提供相关账号密码以供审核人员登录并查看相关信息。
2. 所提交官网需有应用名称字眼及其应用介绍、应用图片、应用提供的服务功能详情等内容，如没有，建议调整网站内容补充更多应用详情内容或修改名称重新提审。
3. 所提交的官网开发者信息（即官网备案的主体信息），需要与微信开放平台开发者资质认证主体信息一致，如不一致，提交时需提供相关授权书（加盖双方公章）以供审核。

关于应用的上架状态，若应用当前仍处于开发调试阶段，则选择「未上架任何应用市场」。

关于「应用流程图」，这里指的是 App 的使用者真实访问 App 后看到的截图，不可提供小程序的截图；如果是基于多端框架开发的 App，可以在开发者工具上通过真机运行的方式，构建安装包并且安装到手机上进行截图；更多审核规范可查看[应用流程图规范](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/operation#%E5%85%AD%E3%80%81%E5%BA%94%E7%94%A8%E6%B5%81%E7%A8%8B%E5%9B%BE)。

「申请/修改应用说明」和「类目」也需要如实填写。

![](https://testchu-7gy8occc8dcc14c3-1304825656.tcloudbaseapp.com/img%2Fmelody%2F202406101814945.png)

### [#](#_3-3-「Android-开发信息」填写) 3.3 「Android 开发信息」填写

应用签名：若应用是基于小程序多端框架开发的，则 Android 应用的签名需按照文档[生成微信开放平台移动应用 Android 签名](../build/open_android_cert)操作。

- 注意：生成签名只和证书的配置有关，和包名无关（即，即使开发者在微信开发者工具构建的 APK 是基于官方分配的测试包名 `com.tencent.weauth` 构建的，也不影响）。

包名：此时需要填写自定义的唯一包名，不可以再填写 `com.tencent.weauth`。

开发方式：选择「传统模式开发」后，再手动绑定移动应用和多端应用即可。

![](https://res.wx.qq.com/op_res/wRJkKuPXbSc4Hu_nZ-fWvh6Gh6Vq1xJCSWuT96LLYEiN0qgyLsm0vqoht84B9zNymCIbWimx1qMChofhFcj4hw)

### [#](#_3-4-「iOS-开发信息」填写) 3.4 「iOS 开发信息」填写

Bundle ID：为开发者自己登录「苹果开发者平台」定义的，可参考 [Apple Developer 平台 Bundle ID 配置指引](../certificate/ios)。

测试 Bundle ID：非必填。

Universal Links：开发者自定义，后续还可修改（故一开始还没有时可先随意填充）。关于填写无效的 Universal Link 会有什么影响，可查看 [Universal Link 配置说明](universal-link-guide)。

开发方式：选择「传统模式开发」后，再手动绑定移动应用和多端应用即可。

### [#](#_3-5-提交审核) 3.5 提交审核
